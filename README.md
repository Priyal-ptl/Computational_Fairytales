# General Summary

Information design has always been a consistent interest of mine, although in the past my work with data usually happened after the analysis stage. I would typically work with existing datasets and focus on presenting the insights in a way that felt engaging and easy to understand.

This class introduced a very different side of that process. Instead of only visualising results, I had to clean the data, run the analysis, and understand how the insights were derived in the first place.

All three projects in this portfolio started from genuine curiosity rather than the dataset itself. The Grimm fairy tales project came from a longstanding interest in folklore and the idea of exploring storytelling structures computationally. The logo clustering project started from a meme... The personality project came from wondering what happens when the same feature vector logic used in recommendation systems is applied to people instead of products.

I'm realizing now that my approach was slightly backwards compared to the structure of the course. I usually started with a question or a visual idea and then worked backwards to figure out what kind of analysis could help explore it...



One thing that did surprised me was how much clearer the mathematical side became once I slowed down and worked through it step by step. Writing out the logic on paper before touching the code helped a lot. Once that clicked, translating the ideas into Python became much easier.

I am still figuring out how deeply I want to pursue data science, but I do recognise how useful it is as a tool. What interests me most is combining both sides of the process: using Python to clean and analyse data, then bringing those results into environments like Illustrator, p5.js, or Processing to explore more expressive forms of visualisation.


## LLM Usage

I have cited the places where I used an LLM within the individual notebooks.

In general I used it for three main things;

1. Understanding difficult concepts
Sometimes I used it to explain mathematical ideas from the lectures in simpler terms when I was stuck.

2. Debugging code
When I encountered errors in Python or during data cleaning, I occasionally used it to help identify what was going wrong.

3. Exploring tools I had not used before
Some parts of my projects involved libraries or methods I had not used before, such as MobileNet feature extraction or NLTK. I used it mainly to understand how those tools worked.
